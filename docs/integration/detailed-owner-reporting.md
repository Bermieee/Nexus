# Detailed owner reporting and selected graph inspection

## Traced gaps

The live 21:33 export showed real traversal and owner execution, but detailed
Brain stages still lacked Scene, Hot Cognition, Retrieval and Runtime evidence.
Sensory's UI projection deliberately emitted an empty candidate array, so the
graph candidate path could not join individual identities to Truth or Gather.
The World Graph inspection reader was absent. Canonical Lore metadata used
ACCEPTED entry states with no study engine; the transplanted adapter counted
every ACCEPTED entry as active work anyway.

## Changes

- Sensory publishes bounded candidate identity/channel/graph metadata without
  bodies. Truth carries the same sensory candidate identity and a compact final
  verdict list, so losing older per-candidate log events does not erase all
  attribution. Coverage remains limited by diagnostic retention and row bounds.
- Successful retrieval returns the candidate IDs for its actual final injected
  references. Gather retains those IDs only from accepted owner results. The
  existing Seal's admitted result IDs then establish the candidate path. A
  shared source revision is no longer treated as individual Gather acceptance.
  Fallback/reused paths without retained candidate IDs remain unproven.
- Brain detail reads exact-generation Scene authority observations, Hot graph
  updates, traversal receipts and Scatter runtime receipts. Jev attempt/return
  evidence is preserved. Sidecar status uses its own resource outcomes rather
  than outcomes of unrelated Jev calls. No provider return implies owner
  acceptance.
- On-demand inspection reconstructs a bounded World Tree graph query using the
  selected generation's saved intent kind, anchors, canonical world revision
  and Lore source fence. It rejects a foreign chat or changed source/world
  revision. Saved plans contain metadata only and share traversal retention and
  clearing. No provider closure or source body is retained. The UI labels this
  as an on-demand read, separately from the historic traversal receipt.
- Canonical-only Lore reads no longer imply an active study job. They explicitly
  say that study execution and retrieval readiness are not reported by this
  owner seam; readiness is not fabricated.

## Bounds and limitations

Candidate diagnostics retain at most 96 rows and 24 references per row. Graph
inspection retains 32 selected-generation plans, 24 anchors and queries at most
96 nodes / 192 edges / 32 candidate edges with the existing 15 ms budget.
Anchor and display overflow counts are explicit. An oversized book/source fence
is not saved incompletely: inspection remains unavailable for that selection.
Old generations without saved plans cannot borrow a current graph read.

The graph view queries canonical owner topology; it does not reconstruct old
scene-only relationships from current chat state. An edited world can invalidate
on-demand inspection while its historic traversal receipt remains visible.
Learning/completion receipt wiring is separate and unchanged here.

## Evidence

`tests/detailed-owner-reporting.mjs` covers metadata bounds/privacy, owner identity
fences, canonical Lore idle status, inspection clearing and stale rejection,
actual canonical graph edges reaching the inspector, actual Gather candidate
acceptance reaching Seal, shared-revision false attribution, retained Truth
identities and independent Jev/Sidecar status. Existing owner, Scene, Sensory,
Graph Walker and selected-turn suites are also checked. Real browser/provider
acceptance still requires another installed generation.
